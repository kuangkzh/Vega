# 需求文档v2

本次需要在v1上做一次较大的架构升级，核心是在v1的基础上，引入 `project` 的概念管理不同项目的会话、code、git、设置项，从而在启动时不需要通过 `-d` 指定工作路径，即可一站式管理多个不同的项目目录。


# project架构

不同的功能属于不同的层级，有些是project级的，有些是全局级别的

## project级

1. 每个project有自己的路径，和im_link参数

2. 会话：和project有归属关系，之前会话的cwd参数，都改用project的路径。之前的会话可以关联监听im，但是全局只能有一个会话关联监听，现在改为每个project下只能有一个会话关联监听，并且使用project独立的im_link参数建立连接。

3. code、git：依赖project的路径，管理和展示该project的路径下的内容

## 全局级别

1. 后台任务：后台任务依旧是全局统一管理，但是每个后台任务需要能关联到创建它的project和会话

2. 设置：除了project路径 和 im_link，其他原有设置都依然作为全局设置


# 功能细节

## 前端功能

不再设置chat、code、git三个分tab，三者集合成一个tab页叫 `工作区` 。

1. `工作区` 延续之前chat页的左右布局，左侧在之前对话列表的基础上，改成 project-chat 二级粒度的展示。具体而言第一层是不同的project列表，每个project可以下拉展开，展开该project下的chat列表，默认是收起状态。顶部的【新建会话】按钮改成【新建project】

2. chat列表项与之前保持不变，点击chat项在右侧打开会话。

3. project列表项中，每一项左侧放一个三角形展示展开/收起的状态，右侧放【+】【⋮‌】两个按钮，【+】是新建会话，【⋮‌】点击展开菜单，展示【code】【git】【设置】三个按钮
    * code：新建窗口，沿用之前的code页展示逻辑，但是只展示当前project的路径
    * git：新建窗口，也是沿用之前git页的展示逻辑，但是只展示当前project
    * 设置：在右侧展示项目设置页，即设置路径和im_link参数
