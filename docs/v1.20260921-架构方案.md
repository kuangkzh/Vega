# Vega 架构方案

> 本文档为设计与实现阶段的唯一架构依据，后续所有设计文档均维护在 `docs/` 目录下。
> 变更需同步更新文末「已确认决策」与「变更记录」。

## 1. 概述

Vega 是一款以编码为主要场景、可扩展插件的 Agent：

- 通过 JSON 配置 agent 参数，`python main.py -c xxx.json -d c:\xxx` 指定配置文件与工作路径。
- 接入 IM（默认飞书）实现 Agent 与用户、Agent 之间的消息交流。
- 通过网页控制台可视化监控与操作 Agent。
- 支持插件体系，插件运行统一经过运行时包装（权限、报错、超长结果处理）。

## 2. 设计原则

- **最简单、最方便开发**，不过度设计。
- **单进程**承载全部能力，减少多进程状态同步复杂度。
- **优先标准库**，仅在必要且经确认后引入新依赖。
- 模块边界清晰，便于扩展（模型协议、消息源、插件均为可替换接口）。

## 4. 并发模型

| 对象 | 实现 | 说明 |
|---|---|---|
| Agent 会话 | `threading.Thread` | 每个会话一个线程跑 Agent Loop |
| 异步 shell | `subprocess.Popen` | 对应需求中的"进程"，主进程退出统一 terminate |
| 异步"等待人工审批" | 后台任务线程 | 受 TaskManager 跟踪，主进程退出随事件结束 |
| 飞书长连接 | 独立线程（`lark-oapi` WebSocket client） | 监听事件，触发新消息/恢复会话 |
| 流式输出 | Flask SSE（generator） | `Response(generator, mimetype='text/event-stream')` |

## 6. 模块职责

| 模块 | 职责 |
|---|---|
| `main.py` | 解析 `-c/-d` 参数，装配依赖，启动 Flask 与 Agent 运行时 |
| `core/` | Agent 会话生命周期、Agent Loop、上下文管理、压缩、后台任务 |
| `models/` | 模型协议抽象与 OpenAI 实现、模型配置管理、token 用量统计 |
| `plugins/` | 内置 + 用户自定义插件；插件基类、权限审批、运行时包装、插件加载 |
| `im_link/` | IM 连接接口与飞书实现（长连接监听 + 发送） |
| `web/` | 控制台页面、JSON API、SSE、鉴权 |
| `storage/` | SQLite 持久化（会话/任务/模型配置） |

### 6.1 插件组织说明

- `plugins/base.py` 为插件框架（`@register_plugin` 装饰器 + 权限/审批 + 运行时包装 + 模块导入加载），无具体插件。
- `plugins/builtin.py` 内置全部基础插件，每个插件为一个函数，用 `@register_plugin` 注册。
- 用户自定义插件为 `plugins/` 下的 `.py` 文件，一个文件可含多个插件函数。
- 注册逻辑：`@register_plugin(description=..., parameters=..., config=..., resolve_permission=...)` 把函数注册进全局 registry（name 取函数名）；`config` 是插件所需配置的「表单 schema」，驱动前端配置表单；`resolve_permission` 默认 `default_permission`（读 permission.default），文件/shell 等特殊权限点由插件显式传入（定义在 `plugins/builtin.py`，与插件绑定）。

### 6.2 内置插件清单（合并于 plugins/builtin.py）

| 插件名（函数） | 功能 |
|---|---|
| `get_last_overflow_result` | 获取上一次超长结果（按行/关键词/行数限制，原 get_last_long） |
| `run_shell` | 执行 shell（`is_async=true` 后台异步执行） |
| `read_file` | 读文件（附行号） |
| `edit_file` | 改文件（行号 / search-replace） |
| `web_fetch` | 网页获取（requests） |
| `request_approval` | 发起权限审批（权限审批流程属于插件功能） |
| `send_im` | 向配置的 IM 接收目标发送消息 |

## 7. 核心流程

### 7.1 Agent Loop（每个会话一个线程）

```
启动：paused=True（默认暂停）
收到第一条消息 → resume → 循环：
  1. 队列取消息 → 追加到对话上下文（role=user，slot 渲染 {{time}}/{{cwd}}）
  2. 检查上下文 token 是否 ≥ 上限×压缩比例 → 触发压缩
  3. call_model(stream=True)（失败重试 `retry` 次，默认 3；报超限 → 触发压缩）
  4. 解析模型输出的工具调用 → 插件运行时执行 → 结果以 role=tool + XML 追加
  5. 无更多任务 → complete 退出循环
```

- 运行状态下新消息只入队，等下一循环追加。
- fork = 复制上下文 + 配置，开新线程。
- 启动时默认创建一个会话。

### 7.2 上下文压缩

- 触发：主动（上下文长度用字符数≈token 轻量概算 ≥ 上限×压缩比例）或被动（模型报 `context length exceeded`）。
- 主动估算不引入 tiktoken，仅作阈值触发；精确 token 口径以模型返回 usage 为准（见 7.6）。
- 动作：保留最近 N 条消息 + 用模型把更早内容总结成摘要注入 system，然后"终止当前会话并启动新会话"（摘要作为新会话初始上下文），未消费的队列消息并入新会话。

### 7.3 插件运行时统一包装（plugins/base.py）

每一次工具调用都走同一管线：

```
解析调用 → 权限检查 → (需审批) 记录入参, 返回 uuid + 提示发起审批
         → (无需审批) 执行(sync/async)
         → 统一返回 {result, msg}
         → msg 若有模板则用 result 渲染
         → result 过长 → 截断 + 存入"上一次超长结果"全局变量 + msg 提示
         → 以 <tool_result name=...>...</tool_result> XML 追加进上下文
         → 异常捕获 → 结构化错误 msg
```

- 统一返回格式：`result`（存放所有结果）+ `msg`（给模型的提示，可含模板，基于 `result` 渲染）。
- 权限等级：`Denied / Trusted / AgentReview / HumanReview`。插件配置统一放在一级 `plugins.<name>`（每插件自持），由 `@register_plugin(config=...)` 声明「配置表单 schema」，配置页据此自动生成表单。
- `Denied` 插件对模型不可见（不进工具列表）。
- `resolve_permission(config, args, cwd)` 读该插件自身配置（直接取 `config.plugins.<name>`）。默认 `default_permission`（读 permission.default）；文件/shell 等特殊权限点由插件显式绑定（`resolve_permission=file_permission`/`shell_permission`，定义在 `plugins/builtin.py`）。

### 7.4 权限审批流程

```
无需审批 → 直接执行返回
需要审批 → 记录入参 → 立即返回 uuid，msg 提示模型用 uuid+理由调用"发起审批"插件
  ├─ AgentReview → 调用审批 Agent（可配额外 prompt）→ 通过/拒绝/加签
  ├─ HumanReview / 加签 → IM 发提醒 → 转异步任务等待人工批准
  └─ 通过 → 自动执行（同步或异步）→ 执行结果追加到上下文
      拒绝 → msg 提示拒绝理由
```

### 7.5 异步执行

- 唯一标识 = `任务名-执行时间`（时间戳到秒，冲突则报错）。
- 传入任务名 + 入参；启动后立即返回任务标识，msg 提示"后台任务提交成功"。
- 完成后：入参、执行时间、完成时间、result、msg 以 `role=tool` 追加到对话上下文。
- `atexit` / signal 注册清理钩子，主进程退出时同步结束所有后台任务（`Popen.terminate()` / 线程置结束标志 join）。

### 7.6 控制台 Web

- 鉴权：单 token（配置写死）；登录页提交 token → 校验通过下发 session cookie，之后所有 `/api/*` 与 SSE 均校验 cookie。
- 前端：`templates` 骨架页 + Vue/Bootstrap CDN 免构建版本，SPA 式切换五个模块（Code/Chat/Git/后台任务/设置）。
- 流式：`/api/sessions/<sid>/stream`（单会话）与 `/api/events`（全局）用 `Response(generator, mimetype='text/event-stream')`；默认折叠思考过程，正式输出开始时收起；工具结果卡片默认收起；后台任务关联展示。
- token 总开销/进度条：只累加模型返回的 usage（input/output/cache），返回结果不含该字段则计 0；不引入 tiktoken。

### 7.7 状态持久化（storage/）

- 存储：SQLite（标准库 `sqlite3`），文件位于 Vega 自身 `data/vega.db`（全局共用一个库，不随 `-d` 工作目录，避免污染打开的项目）。
- 需恢复的状态：Chat 会话（默认暂停 + Resume 按钮）、后台任务记录与输出（模型配置不在 DB，而是维护在配置 JSON 的 `models` + `active_model`）。

### 7.8 IM 连接（chat_id + 会话绑定监听）

- IM 配置字段 `im_link.chat_id`（原 `admin_open_id`）用于审批通知与 `send_im` 插件的接收目标，发送时 `receive_id_type="chat_id"`。
- 入站：应用级长连接收到消息后，投递到「当前绑定的 IM 监听会话」；启动时不绑定，需在会话列表点击连接 icon 建立监听，同一时间仅一个会话监听（点击已绑定 icon 可断开），避免重复投递。
- IM 入站消息等同于网页控制台输入，仅在末尾追加「（本消息来自 IM）」。

## 9. 依赖清单

| 依赖 | 用途 | 状态 |
|---|---|---|
| `requests` | HTTP 请求（模型 / 飞书发送 / 网页获取） | 已允许 |
| `Flask` | Web 服务器 | 已允许 |
| `jinja2` | 模板渲染 | 已允许 |
| Vue / Bootstrap（CDN） | 前端 | 已允许（免构建） |
| `lark-oapi` | 飞书官方 SDK：**长连接监听事件** + 事件解密 | 已允许（经确认） |
| `html2text` | `web_fetch` 的 markdown 模式把 HTML 转 Markdown | 已允许 |

标准库即可、无需新依赖的能力：

- Git 模块 → 调用系统 `git` 命令（`subprocess`），不引入 `gitpython`。
- 异步执行 → `subprocess` + `threading`（标准库）。
- 数据库 → `sqlite3`（标准库）。
- 飞书**发送消息** → `requests` 直连（自建应用 tenant_access_token）。
- token 统计 → 直接用模型返回 usage，无需 `tiktoken`。

> 说明：飞书"长连接监听事件"经确认引入 `lark-oapi`（官方 SDK，含 WebSocket 长连接与事件解密）；飞书"发送消息"仍可直接用 `requests`。
