# 实现草稿：配置 / 权限 / 审批 / 运行时

> 本文档是《架构方案》实现阶段的补充草稿，沉淀实现层面易出歧义的约定。
> 定稿要点会回写 `docs/架构方案.md` 并在「变更记录」登记。

## 1. 配置文件 schema（config/default.json）

| 字段 | 类型 | 说明 |
|---|---|---|
| system_prompt | string 或 `{"file": "x.md"}` | 直接文本；或从 .md 路径导入（相对 cwd）。支持 `{{time}}`、`{{cwd}}` 槽位 |
| model | object | 初始/默认模型配置（base_url/api_key/model/max_context/compress_ratio 及 input/output/cache 三档价格）。`id` 缺省取 `name` |
| retry | int | 连接模型失败重试次数，默认 3 |
| approver | object | 审批 Agent 配置：`model`（模型 ID）、`prompt`（额外提示词，要求输出 JSON） |
| feishu | object | `enabled`、`app_id`、`app_secret` |
| web | object | `host`、`port`、`token`（单 token 鉴权） |
| permissions | object | 默认等级、shell 正则名单、插件明细等级、外部文件默认等级 |

`permissions` 结构：

```json
{
  "default": "Denied",
  "external_file": "AgentReview",
  "shell": {
    "denied": ["..."],
    "human_review": ["..."],
    "agent_review": ["..."],
    "trusted": ["..."]
  },
  "plugins": {
    "read_file": { "global": "AgentReview", "cwd": "Trusted", "external": "AgentReview" },
    "run_shell": { "global": "HumanReview" }
  }
}
```

## 2. 权限解析算法

- 等级枚举：`Denied / Trusted / AgentReview / HumanReview`。
- 通用插件：取 `plugins.<name>.global`，缺省用 `permissions.default`（默认 Denied）。
- 文件类插件（read_file/edit_file）：按路径是否在 cwd 内选 `cwd` 或 `external` 键，缺省回退 `global`；`external` 缺省回退 `permissions.external_file`（默认 AgentReview）。
- shell 类插件（run_shell / run_shell_async）：把命令依次匹配 `denied → human_review → agent_review → trusted` 四组正则，首个命中即用该等级；均未命中默认 `HumanReview`。
- `Denied`：插件对模型不可见（不进 tools 列表），调用直接拒绝。

## 3. 插件运行时 & 审批流程

执行管线（`plugins/base.py` 的 `execute`）：

1. `resolve_permission` 得出等级。
2. `Trusted` → 直接执行；`Denied` → 直接拒绝返回。
3. `AgentReview/HumanReview` → 记录一次「待审批请求」（入参 + 随机 uuid），立即返回 `{result: {}, msg: "该操作需要审批，uuid=<uuid>，请调用 request_approval 发起审批"}`。
4. 模型随后调用 `request_approval`（入参：uuid、任务名、理由）：
   - AgentReview → 调审批 Agent（额外 prompt），返回 `approve/reject/escalate`。
     - approve → 立即执行原插件，返回结果。
     - reject → msg 提示拒绝理由。
     - escalate → 转人类审批（同下）。
   - HumanReview（或 escalate）→ 经飞书发提醒；创建后台任务（`pending_approval`），返回任务标识 + msg「已提交后台审批」；人工通过后自动执行并追加结果。
5. 统一返回 `{result, msg}`；msg 若含模板则用 result 渲染；result 过长→截断并存入「上一次超长结果」，msg 提示；最终以 `<tool_result name=...>` XML 展开追加进上下文。

## 4. Agent Loop 伪代码

```
resume 后循环：
  messages = [system(slot 渲染)] + 历史
  ev = model.chat_stream(messages, tools=可见工具)
  逐 text 事件推送前端；收集 tool_calls / usage
  usage 累加到会话 token_usage；若估算超限→压缩
  若 tool_calls：
    逐个 execute() → tool role 追加（tool_call_id 对应）
    回 loop 继续
  否则：文本输出结束；若无更多任务→pause
```

## 5. 异步任务生命周期

- 唯一标识 `任务名-执行时间`（冲突报错）。
- 后台任务登记进 `store`（status=running/pending_approval/done/error/cancelled）。
- 完成回调：入参/执行时间/完成时间/result/msg 以 `role=tool` 追加对应会话上下文。
- 主进程退出：atexit 统一 terminate 子进程、join 线程并标记任务结束。
