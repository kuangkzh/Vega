# Vega v2 架构文档

> 对应需求：`docs/v2.20261017-需求文档.md`
> 本文档描述 v2 引入 project 概念后的架构，供后续开发者阅读。变更请同步更新本文档。

## 1. 概述

v2 在 v1 基础上引入 `project`，用于一站式管理多个项目目录，启动时不再绑定单一工作目录。

- **project 级**：路径（path）、im_link 参数、会话（ChatSession）、code、git。
- **全局级**：后台任务（需关联创建它的 project 与 session）、除 path/im_link 外的所有设置（模型、system_prompt、插件配置、approver、summarizer 等）。

## 2. 启动

- 入口：`python main.py -c config/xxx.json`
- 回退工作路径取 Vega 目录本身，正常由 `project.path` 覆盖。
- 持久化数据库：`data/vega_v2.db`。

## 3. 目录结构

```

│   ├── agent.py               # AgentSession + Agent Loop
│   ├── session_manager.py     # project + 会话 + IM 监听管理
│   ├── context.py             # 模板渲染 / token 估算
│   └── task_manager.py        # 后台任务登记、执行、退出清理
├── models/
│   ├── base.py                # 模型抽象 + 重试
│   └── openai.py              # OpenAI 协议实现
```

## 4. 数据模型与持久化

### 4.1 表结构（SQLite，`vega_v2.db`）

| 表 | 关键列 | 说明 |
|---|---|---|
| projects | id, path, im_link(JSON), created_at, updated_at | 项目，path 是会话/插件/code/git 的工作目录 |
| sessions | id, project_id, created_at, updated_at, status, token_usage(JSON) | 会话，属于某个 project |
| tasks | id, name, session_id, project_id, start_time, end_time, status, pending_approval, params, result, logs | 全局后台任务，关联 project/session |
| messages | id, session_id, role, content, reasoning_content, tool_calls, tool_call_id, name, task_id, created_at | 会话消息，不变 |

### 4.2 关键关系

- `session.project_id` / `task.project_id` 归属 project。
- `message.session_id` 归属 session，不直接关联 project。
- project 的 `im_link` 为 JSON 对象，结构与服务端 `build_im_link` 约定一致（`type/app_id/app_secret/chat_id`）。

## 5. 模块职责

| 模块 | 职责 |
|---|---|
| `main.py` | 解析 `-c`，装配 store/runtime/manager，启动 Flask |
| `core/session_manager.py` | project CRUD、会话创建/调度/fork/压缩重启、IM 监听、project 上下文解析 |
| `core/agent.py` | 单会话 Agent Loop，工具调度，上下文管理 |
| `core/task_manager.py` | 后台任务全局唯一标识、线程执行、状态持久化、退出清理 |
| `plugins/runtime.py` | 插件框架、权限解析、运行时包装、审批编排、project cwd/im_link 注入 |
| `im_link/` | IM 连接接口与飞书实现；每个 project 独立实例 |
| `web/` | 控制台页面、JSON API、SSE、鉴权 |
| `storage/` | SQLite 持久化 |

## 6. 核心流程

### 6.1 project 上下文解析

`SessionManager._project_context(session_id)` 是插件运行时与 project 的桥梁：

```
session_id → session.project_id → project
  return {
    project_id, cwd(project.path),
    im_link(该 project 的 ImLink 实例),
    im_config(project.im_link 字典)
  }
```

`PluginRuntime.project_resolver` 在 `SessionManager.__init__` 中被赋为该函数；`PluginRuntime.execute/_resolve_project` 用它得到每个会话的 cwd/im_link/project_id。

### 6.2 IM 监听（每个 project 独立）

- `load()` 时为每个 project 调用 `start_project_im(pid)`：按 `project.im_link` 构建 `ImLink` 并 `start()`。
- project 创建/更新时同步（重）建连接。
- 每个 project 内仅一个会话监听 IM：`toggle_im(project_id, sid)`，状态存 `_im_session_by_project`。
- 入站消息投递给该 project 当前绑定的会话：`im_recv(project_id, text)`。

### 6.3 会话与插件执行

- 会话创建必须携带 project（`create(project_id)`），其 `cwd` 取 `project.path`。
- Agent Loop 中 `runtime.visible_tools(cwd)` 按当前 cwd 计算（文件权限区分 cwd 内/外）。
- 工具执行 `runtime.execute(name, args, session_id)` 经 resolver 注入 `im_link/im_config/project_id`。
- `send_im` 使用 `ctx.im_link` + `ctx.im_config.chat_id`（即该项目自己的 IM 目标）。
- 异步 shell 提交 `tm.submit(..., project_id=ctx.project_id)`，审批通知也用该项目的 `im_link`。

### 6.4 后台任务与审批

- 后台任务仍全局统一管理，`TaskManager.submit(..., project_id=...)` 记录归属。
- 人工审批通知发给对应 project 的 IM 链接；任务等待人工批准后自动执行。

## 7. Web 控制台

### 7.1 页面（前端 nav）

- 三个 tab：**工作区 / 后台任务 / 设置**。
- 工作区内部用 `workspaceView` 切换：`chat | code | git | project_settings`。
- project 菜单：`code`/`git` 用 `window.open('/?view=code|git&project=...')` 打开新窗口；`设置` 在右侧编辑 path/im_link。

### 7.2 前端数据流

- `loadProjects()` 拉取 `/api/projects`，得到 `projects[].sessions`。
- 全局 SSE `/api/events` 实时同步 `session` / `project` 事件到 `projects` 数组。
- code/git API 请求统一携带 `project`（query）或 `project_id`（body）。

### 7.3 主要 API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET/POST | /api/projects | 列表 / 新建 |
| PUT/DELETE | /api/projects/<pid> | 更新 / 删除 |
| GET/POST | /api/sessions | 按 `project_id` 过滤 / 新建会话 |
| POST | /api/sessions/<sid>/fork, /resume, /pause, /im/toggle | 会话操作 |
| GET | /api/sessions/<sid>/stream, /api/events | 会话 SSE / 全局 SSE |
| GET/POST | /api/browse, /api/file, /api/file/diff | 文件浏览（带 project） |
| GET | /api/git/branches, /api/git/log, /api/git/status | git（带 project） |
| GET | /api/tasks | 后台任务（含 project_id） |
| GET/POST | /api/config, /api/models, /api/plugins | 全局设置（不含 project im_link） |

## 8. 鉴权

- 单 token（`config.web.token`），登录后下发 session cookie；`/api/*` 与 SSE 校验 cookie。

## 9. 注意事项

- 旧 `templates/index/_chat.html、_code.html、_git.html` 不再被引用，属历史文件。
- 持久化库为 `data/vega_v2.db`。
- 文件读写/git 均以 project.path 为根，`web/code.py` 的 `_cwd()` 负责解析并防止目录穿越。
