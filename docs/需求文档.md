# 需求文档

CodeAgent旨在设计一款主要为编码设计的Agent，但并不局限于Code能力，支持额外的插件开发和引入；支持接入飞书来实现Agent与用户、Agent之间的交流；通过网页版控制台来可视化控制Agent允许。

## 技术选型

优先使用python作为主要程序语言，使用requests做http请求，Flask做服务器，jinja用于模板渲染，前端可以使用bootstrap或vue的CDN免构建版本做框架，如需引入其他依赖需要与我说明原因，由我同意。

## 功能细节

1. Agent核心
    * 支持通过json来配置agent参数，通过`python main.py -c xxx.json -d c:\xxx`来指定配置文件和工作路径
    * agent参数：`system_prompt`（允许直接写文本或指定路径）、模型的调用配置、飞书的APP_ID/SECRET、插件的权限设置、其他必要的参数
    * system_prompt：配置中的system_prompt需要允许直接给定prompt文本或给定.md路径导入两种形式，同时需要允许prompt中设置{{time}}、{{cwd}}等槽位替换当前时间、工作路径等
    * 启动时默认处于暂停状态，直到收到新消息。在运行状态下新消息放入队列，直到下一循环追加到对话上下文
    * 支持创建多个agent会话，并可从任意问句 fork 出新会话分支，多个会话并行执行，启动时默认启动一个会话
    * 当上下文长度超设置上限或者超限报错时，触发上下文压缩，终止当前会话并启动新的会话
    * 连接模型失败时默认重试3次

2. 插件
    * 建立plugins文件夹，支持agent依据配置读取和使用其中的插件
    * 对插件做统一的运行时包装，处理权限审批、报错、返回过长的问题，对超长的结果保存成全局变量，并允许通过插件分行或检索获取“上一次超长的结果”
    * 插件返回格式：返回格式统一包含`result`、`msg`，`result`用于存放所有返回结果，`msg`用于给模型提示信息，`msg`可以包含模板，并基于`result`渲染最终结果。最终结果给到模型上下文时用XML格式展开。
    * 异步执行：插件启动异步执行时，需要传入任务名、入参，以`任务名-执行时间`为唯一任务标识。如果标识不唯一则报错提示，任务启动后返回任务标识，并在`msg`中提示后台任务提交成功。后台执行后，等待完成拿到最终执行结果，再将入参、执行时间、当前时间、`result`、`msg`用role为tool追加到对话上下文。注意所有异步执行的进程必须在主进程结束时同步结束。
    * 基础插件需求
        * 暂停任务：暂时没有更多的任务可以做了，调用本插件，暂停Agent Loop
        * 获取上一次超长结果：支持按行，或者以关键词检索行内容，两个条件可叠加筛选，限制返回结果行数。
        * 执行shell：通过bash执行shell命令
        * 读取文件：读入一个文件的全部内容，读入内容加上行号
        * 修改文件：支持按行号或者search/replace块修改文件
        * 网页获取：获取指定url的内容
        * 异步执行shell：给定任务名和shell命令，启动后台异步执行
        * 发起权限审批：填入权限申请uuid，填写任务名、申请理由，发起审批，审批通过后自动执行（可能同步也可能异步）
        * 发送飞书消息：通过飞书发送一条消息
    * 权限机制：权限分Denied、Trusted、Agent review、Human review几个等级，插件内部可以细分特殊权限
        * Denied：禁止使用，Denied插件模型不可见，在配置文件中，若无特别标注则默认Denied
        * Trusted：可以直接执行
        * Agent review：需要另一个Agent进行审批，这里的审批Agent需要能配置额外的prompt，审批Agent可以选择拒绝、通过、加签，加签即要求人类用户再次审批决定是否通过。
        * Human review：直接由人类用户进行审批
        * 细分权限：插件内部可以设置更细的权限，比如读取文件区分cwd下和外部文件使用不同的权限要求
        * 权限审批：如果无需审批，则直接执行并返回。如果需要审批，则记录入参，立即返回一个随机生成的uuid，并在`msg`中提示模型需要用uuid填写理由发起审批。发起审批后，如是Agent审批则调用审批Agent，若执行则直接返回结果，若拒绝则在`msg`中提示拒绝理由。若加签人类审批或必须人类审批，通过飞书发送消息提醒，然后启动异步执行，返回任务标识，后台等待审批通过自动执行，执行完成再将执行结果追加到对话上下文。

3. 控制台网站：可以监控和操作整个Agent的执行，需要适配移动端和桌面端。分以下的功能模块：
    * Code：编码区，可以从文件目录打开文件，查看、编辑文件内容，并看到修改内容。
    * Chat：对话区，可以看到全部agent会话，发送新消息，在运行状态下新消息放入队列，并支持取消，流式输出响应，默认折叠展示思考过程并在正式输出开始时收起，展示工具执行结果卡片（默认收起），关联异步任务到后台任务。支持展示上下文进度条，统计token总开销，支持创建新会话，并可从任意问句 fork 新会话。
    * Git：展示Git分支和commit、merge历史
    * 后台任务：展示所有在后台执行的任务名、执行时间、状态，并支持展开输出日志。待审批任务也在这里展示。按执行时间倒序展示，并支持按状态筛选，支持url中带参筛选任务名以方便审批消息通知
    * 设置：对agent配置进行可视化设置
    * 登录页：以上功能都需要使用鉴权token登录后才可访问

4. 模型连接：暂时以openai协议作为模型调用默认方式，抽象通用接口方便扩展其他协议，对每个模型可以设置输入、输出、cache命中价格，上下文上限、上下文压缩触发比例

5. 消息连接：暂时以飞书作为默认消息发送渠道，定义以下接口，方便扩展其他消息源
    * 发送消息
    * 接收消息回调

6. 状态维护：有些允许状态需要持久化维护，并在下次启动时恢复
    * Chat：所有会话状态需要保存，但在下次启动时默认处于暂定状态，并展示一个Resume按钮
    * 后台任务：需要保存所有后台任务的执行记录和输出，但是在主进程退出后结束所有后台任务
    * 模型配置：允许新建和管理模型配置，支持快速切换模型配置
